# Вега-М — инфо-киоск (прайс, расписание, врачи)

Сервер отдаёт JSON и сам клиент, сенсорный ПК открывает страницу в полноэкранном
браузере. Пароль к базе остаётся на сервере и на киоск не попадает.

## Что где

| Часть | Расположение |
|---|---|
| Сервер + клиент | `C:\Users\Администратор\vegasrv\kiosk` |
| Реквизиты БД | `C:\Users\Администратор\.claude\tools\db\kiosk_config.json` (ACL: SYSTEM, Администраторы, Администратор) |
| Вьюхи в базе | `..\.claude\tools\db\kiosk_views.sql` (применено 2026-10-26) |
| Логи | `logs\server.log`, `logs\supervisor.log`, `logs\stdout.log` |
| Снимки для офлайна | `data\price.json`, `data\schedule.json`, `data\doctors.json` |
| Документы и материалы | `docs\` — описания проекта, `screenshots\`, `dumps\`, `source\`, `preview\` |

## Запуск и управление

Служба-задача планировщика **«Vega Kiosk Server»** (AtStartup, S4U, Highest):
работает без входа в систему, при падении `run_server.ps1` перезапускает `node` через 5 с.

```powershell
Start-ScheduledTask   -TaskName 'Vega Kiosk Server'
Stop-ScheduledTask    -TaskName 'Vega Kiosk Server'
Get-ScheduledTaskInfo -TaskName 'Vega Kiosk Server'
```

Вручную (для отладки, без планировщика): `node server.js` в этой папке.
Порт задаётся `VEGA_KIOSK_PORT` (по умолчанию 8080), путь к конфигу — `VEGA_KIOSK_CONFIG`.

## API

| Метод | Что отдаёт |
|---|---|
| `GET /api/price` | 5144 услуги с действующей ценой |
| `GET /api/schedule` | смены с сегодняшнего дня (только опубликованные врачи) |
| `GET /api/doctors` | врачи с биографиями |
| `GET /api/photo/:id` | фото врача (ETag; сводка кэшируется в памяти и сверяется с БД по подписи «дата+размер», клиент запрашивает с `?v=PHOTO_KEY`) |
| `GET /api/health` | состояние БД и кэшей |

Кэш: прайс 10 мин, расписание 2 мин, врачи 30 мин. Если база недоступна — отдаётся
последний удачный снимок из `data\`, клиент показывает жёлтую плашку.

## Настройки

`kiosk_config.json`, необязательный блок `schedule`:

```json
{ "schedule": { "showUnpublished": true } }
```

По умолчанию расписание фильтруется по `IS_PUBLISHED_WEB = 1` (46 врачей из 79,
12 врачей со сменами скрыты).

Раздел «Врачи» **не** фильтруется по этому признаку: источник истины —
справочник врачей Archimed (вьюха уже отсекает служебные роли — администраторы,
медрегистраторы, медсёстры, бухгалтер, биолог и служебная запись «Администратор
ArchiMed+»). `IS_PUBLISHED_WEB` (`SHOWING_SCHEDULE_WEB`) означает лишь
«публиковать расписание на сайте», поэтому врач без онлайн-расписания всё равно
показывается.

Исключение одно: врач, у которого **нет ни одной смены** в
`v_kiosk_schedule` (смены с сегодняшнего дня), в списке не показывается.
Признак `HAS_SCHEDULE` считает сервер в `loadDoctors()` подзапросом к вьюхе
расписания, клиент по нему фильтрует (`renderDoctors()`). Следствие: если у
работающего врача закончились внесённые смены и новые ещё не завели, он
временно пропадёт из списка — это ожидаемо.

Главный врач вынесен **первым островком** «Главный врач» (и первым чипом в полосе),
чтобы его не искали глазами среди 36 специальностей; в островке «Кардиолог» он
показывается ещё раз — как любой врач с несколькими специальностями.

Плашка **«Главный врач»** берётся из Archimed, а не из списка в коде: во вьюхе
`v_kiosk_doctors` есть флаг `IS_CHIEF` (EXISTS по типу «Главный врач» в
`DOCTORTYPES` с `ENABLED = 1`). Сама роль из списка специальностей по-прежнему
исключена, поэтому островком «Главный врач» не появляется — клиент просто рисует
плашку под специальностью на карточке и в модальном окне. Сейчас помечена
Ефимова Ю. А. (кардиолог; основная специальность у неё остаётся «Кардиолог»,
роль «Главный врач» — дополнительная).

Из этого правила есть исключения — врачи, которых показываем всегда, даже без
смен: список `ALWAYS_SHOW_DOCTORS` в `server.js` (сравнение по ФИО без учёта
регистра, пробелов и «ё/е»). Сейчас там выездной нарколог Угрюмов Дмитрий
Михайлович: смены ему в Archimed не заводят никогда, а в справочнике киоска он
нужен. Сервер ставит такому врачу `HAS_SCHEDULE = 1`, клиент не меняется.

## Раздел «Врачи»: островки по специальностям

Вьюха `v_kiosk_doctors` отдаёт одну строку на пару «врач + специальность»
(источник — `DOCTORS_EXTTYPES_CONTENT`, а не единственное поле `DOCTORS.TYPE`).
Клиент группирует строки в островки, поэтому врач с двумя специальностями
показывается в обоих; в модальном окне перечислены все его специальности.

Служебные роли (Администратор, Медрегистратор, Лаборатория, Лаборант,
Процедурная медсестра, Бухгалтер и т.п.) исключены в самой вьюхе — список
в `kiosk_views.sql`, блок `v_kiosk_doctors`. Если какую-то роль нужно вернуть
или убрать, правится этот список, затем скрипт применяется заново
(`kiosk_apply.ps1`). Сверху — полоса чипов для быстрого перехода к островку.

Карточки врачей идут по три в ряд, фото — почти квадратные (в базе ~1:1.05,
220–600 px), поэтому рамка 1:1.02 и `object-position: center 38%` не режут
лица; имя и специальность по центру, как на сайте. Заголовки островков
«липкие» — при прокрутке специальность остаётся на виду.

## Запись на приём

На сайте клиники запись идёт не через личный кабинет, а через штатный виджет
Archimed (`widget.archimed-soft.ru`, ключ `5419681901a9d13534c34fae0731eaeb`).
Киоск открывает тот же виджет в оверлее по красной кнопке «Записаться на приём»:
талон создаёт сам Archimed со всеми правилами клиники, записи в базу и
создания пациентов с нашей стороны нет.

- Нужен доступ в интернет с киоска до `widget.archimed-soft.ru`. Если iframe
  не загрузился за 8 секунд, показывается телефон регистратуры.
- Автосброс в записи — 90 секунд бездействия. События внутри iframe Archimed
  нашему документу не видны, поэтому нажатия по форме таймер не сбрасывают;
  чтобы данные не пропадали молча, за 10 секунд до закрытия появляется окно
  «Запись закроется через N с» с кнопкой «Продолжить запись» — нажатие
  продлевает ещё на 90 секунд. Если не нажать, киоск вернётся на главный
  (`BOOKING_IDLE_MS = 90 с`, `BOOKING_WARN_MS = 10 с` в `app.js`).
- Закрытие — крестиком в шапке, внизу под виджетом кнопка «На главный экран»
  (та же, что в разделах), после чего киоск возвращается на главный экран.
- Масштаб виджета: внутрь чужого iframe вклиниться нельзя, поэтому увеличиваем
  его целиком — `.booking-body` в `style.css` задаёт `--booking-zoom` (сейчас
  1.4): iframe раскладывается в уменьшенном вьюпорте (`100% / zoom`) и
  растягивается `transform: scale()`, текст крупнее, обрезки нет. Рабочий
  диапазон 1.3–1.45; выше — виджету становится тесно (поля и кнопки начинают
  ужиматься).

## Раздел «Расписание»

Смены выбранного дня тоже разложены по островкам специальностей (та же
логика: смена врача с двумя специальностями показывается в каждом островке).
Специальности берутся из справочника врачей (`/api/doctors`), поэтому при
открытии расписания подгружается и он; если врач там не найден, используется
специальность из самой смены. Внутри островка смены отсортированы по времени
начала, подпись специальности под именем убрана — она дублировала заголовок.

## Клиент на сенсорном ПК

Открыть в полноэкранном режиме (Edge установлен на Windows по умолчанию):

```
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --kiosk http://192.168.88.53:8080 --edge-kiosk-type=fullscreen --no-first-run
```

**Автозапуск без видимого браузера** — задача планировщика **«Vega Kiosk Browser»**,
её ставит `install_browser.ps1` (запускать на сенсорном ПК от администратора):

```powershell
powershell -ExecutionPolicy Bypass -File install_browser.ps1
# другой адрес или имя задачи:
powershell -ExecutionPolicy Bypass -File install_browser.ps1 -Url 'http://192.168.88.53:8080/' -TaskName 'Vega Kiosk Browser'
```

Задача срабатывает при входе пользователя в Windows и запускает Edge в режиме
`--kiosk`: без рамки, адресной строки, вкладок и панели задач. При падении браузер
перезапускается (до 3 раз), ограничения по времени работы нет.

`install_browser.ps1` сохранён в UTF-8 **с BOM** и содержит кириллицу. Windows
PowerShell 5.1 читает `.ps1` без BOM как ANSI (cp1251), и русский текст ломает
разбор скрипта — вылезают «Непредвиденная лексема» и кракозябры. Пересохранять
файл только как «UTF-8 with BOM» (или правки делать латиницей).

Скрипт также задаёт политики Edge в `HKLM:\SOFTWARE\Policies\Microsoft\Edge`:

- первый запуск и импорт: `HideFirstRunExperience=1`, все `Import*=0`,
  `DefaultBrowserSettingEnabled=0`, `InPrivateModeAvailability=1`;
- запуск и фон: `StartupBoostEnabled=0`, `BackgroundModeEnabled=0` — иначе Edge
  держит процесс после закрытия окна, новый запуск с `--kiosk` подключается к
  старому экземпляру, флаги игнорируются и открывается стартовая страница
  (например, Яндекс);
- стартовый адрес: `RestoreOnStartup=4` + подраздел `RestoreOnStartupURLs`
  (значение `1` = адрес киоска), `HomepageLocation`, `NewTabPageLocation`,
  `HomepageIsNewTabPage=0`, `ShowHomeButton=0`.

Пропустить политики — ключ `-SkipPolicies`; откатить — удалить ветку
`Microsoft\Edge` в `Policies`. Перед запуском задачи скрипт дважды закрывает
Edge (второй проход добивает фоновый процесс), запускает задачу, проверяет, что
есть процесс с `--kiosk`, и проверяет `/api/health` с этого ПК.

Удалить:

```powershell
Unregister-ScheduledTask -TaskName 'Vega Kiosk Browser' -Confirm:$false
```

Важно: задача запускается после входа в систему, поэтому для полностью
автоматической загрузки на ПК должен быть включён автовход Windows
(`netplwiz` → снять «Требовать ввод имени пользователя и пароля»). Пароль
в скрипт не записывается.

Если нужно полностью заблокировать выход из киоска (Alt+F4, Win и т. п.),
дополнительно настраивается «Назначенный доступ» Windows (Assigned Access) —
это отдельная настройка, скрипт её не делает.

Порт открыт в брандмауэре правилом **«Vega Kiosk HTTP»** (TCP 8080, профили Domain/Private).

## Если что-то не так

- `curl http://192.168.88.53:8080/api/health` — `ok:true` и `source:"db"` у всех лент.
- `source:"stale"` — база недоступна, киоск живёт на снимке; смотреть `logs\server.log`.
- Киоск не открывает страницу — проверить правило брандмауэра и что задача запущена.
- Обновили статику — поднять номер `?v=N` у `style.css` / `app.js` в `index.html`
  (в проде статика кэшируется на час, сам `index.html` отдаётся с `no-store`,
  поэтому новый номер подхватывается при следующей перезагрузке киоска).
  Клиент сам перезагружается при смене `?v=N` (сверяет `/api/version`), но **не
  делает этого, пока открыта запись или документ** — иначе посетитель потеряет
  заполненную форму.
